### OpenFace 查证结论（新增）

- 本机**没有**原生 OpenFace 二进制（`FeatureExtraction` 不在 PATH），但**有 Docker 镜像**：
  - `benbuleong/openface-cambridge-2.2.0:latest`（14.4GB）—— 正是 `openface_pipe.py` 的 `DEFAULT_DOCKER_IMAGE`
  - `adhd-openface:2.0.3`（5.93GB，ADHD 项目自建）
- Docker Desktop 在跑（searxng 容器 Up 26h），`docker info` 正常。
- **已实测**：`docker run --rm --platform linux/amd64 ... ./FeatureExtraction --version` 成功加载全部模型（CLM/PDM/patch experts/eye modules），exit=0。
- **之前 AU 全部 `insufficient_data` 的原因**：跑 P-0086 任务时 Docker 未运行 / 镜像未就位，`docker_available()` 返回 False → openface 降级为未提取。
- **结论**：现在重新跑任务即可拿到 AU（AU01–AU26、AU45 共 17 项），情绪波动 / 反应控制类将重新有数据。**整合后需重跑一次真实任务验证 AU 链路。**

## 一、原型审查结论（功能 / 交互 / 信息架构）

### 1.1 信息架构（6 组 18 页，已确认合理）

| 分组 | 页面 | 性质 | 结论 |
| --- | --- | --- | --- |
| 01 工作台 | index | 总览入口 | ✅ 保留 |
| 02 视频分析 | analysis / batch / capture / tasks | 输入与任务 | ✅ 保留，接后端 |
| 03 数据与分析 | data / profile / semantic / markers / alignment / indicators | 结果展示 | ✅ 核心，接 portrait.json |
| 04 事件与预警 | special / alerts | 结果展示 | ✅ 接 cards / alerts |
| 05 报告与追溯 | reports / report / logs | 结果展示+导出 | ✅ 接 portrait.json + 文件导出 |
| 06 系统管理 | models / settings | 配置与诊断 | ⚠️ 部分保留（见 1.3） |

### 1.2 交互设计（已确认）

- 统一六组导航、18 页跳转、全局搜索、任务选择器、移动端折叠菜单 → 交互合理，保留。
- 单视频/批量/现场采集的"先校验元数据、再登记任务"交互 → 与后端"上传视频才建任务"的模型**需统一**（见 2.2）。
- 复核状态跨页同步（reviews）→ 本版不纳入持久化，前端仅保留本地 localStorage 体验。
- 任务状态流转需映射（见 2.3）。

### 1.3 需处理的点（审查发现）

1. **AU 链路**：本机 OpenFace 可用（Docker），AU 可提取；但**需重跑任务验证**，且 AU 提取耗时显著（14.4GB 镜像 + amd64 模拟，单视频可能数分钟到十几分钟）。
2. **"反应控制"类**：当前 face_accel/head_thrust 由头部运动代理，愤怒/厌恶 AU 缺失。AU 恢复后需核对子项归属，避免"头部运动冒充愤怒"的误导。
3. **模型管理页**：接 `/api/health` 扩展后的真实诊断（见 2.4），其余"未接入/未知"保留。
4. **生理信号（rPPG 心率/HRV/呼吸）**：v1 明确不做，原型中相关标志物降级为"未提取"。

| 维度 | 原型命名 | 后端真实命名 |

### 2.2 输入模型需统一

- 原型：先登记元数据任务（queued），视频只读不上传。
- 后端：`POST /api/jobs` 需要实际视频字节流（上传后才 start `_work` 线程）。
- **结论**：改造为"上传视频 → 后端建任务并立即进入队列"；原型的"本地元数据预检"保留为前端体验，最终以 `POST /api/jobs` 为唯一建任务入口。现场采集（capture）录制的 WebM 也走同一上传。

### 2.3 状态 / 阶段映射（我的判断）

**状态映射（后端 4 态 → 原型 6 态）：**

| 后端 status | 原型 status | 说明 |
| --- | --- | --- |
| queued | queued（待处理） | 一致 |
| running | processing（解析中） | 一致 |
| done | completed（已完成） | 一致 |
| failed | failed（解析失败） | 一致 |
| — | partial（部分失败） | **本版不启用**，前端隐藏该状态入口（后端无此模型） |
| — | cancelled（已取消） | **本版不启用**，后端无取消接口 |

**阶段映射（后端 stage 粗粒度 → 原型 9 阶段里程碑）：**

- 后端 stage 只有 `queued / extracting / scoring / done / failed`，不足以支撑 9 阶段精确进度。
- **方案（推荐）**：前端把 9 阶段保留为"里程碑展示"，进度条用后端 stage 推导：
  - `queued` → 阶段 0
  - `extracting` → 阶段 1–7（文件导入→…→突变检测），进度条走到约 80%，文案"特征提取中"
  - `scoring` → 阶段 8（报告生成中）
  - `done` → 9 阶段全亮
- **不做**：伪造 9 步精确百分比。若需真实分步进度，需 pipeline 各 package 完成时回写 stage 到 DB（列为二期可选，中等改动）。

## 三、重点指标推荐（2-3 个重点展示）

> 筛选标准：① 契合平台"情绪算法/心理画像"方向；② 可解释性强；③ 有充分真实数据支撑。

### 数据现实（实测 P-0086 任务 + OpenFace 已恢复）

- ✅ 确定可用：**语音声学**（f0 194Hz、energy、spectral_centroid、zcr、MFCC×13）、**语音韵律语义**（语速 341cpm、停顿、语段 145、填充词 4、ASR 置信度 0.81）、**视觉**（head/gaze 492 点）、**眨眼**（102 次）。
- ✅ 恢复后可用：**AU 17 项**（需重跑任务验证）。
- ❌ 不可用：**生理 rPPG/心率/HRV/呼吸**（v1 不做）。

### 推荐方案（1 主 + 2 辅，已确认落地）

**① 语音情绪唤醒度（Vocal Arousal）—— 头牌·描述性指标** ⭐
- 构成：基频 f0 均值/方差 + 短时能量 energy_db（+ 频谱质心辅助）。
- 可解释性：情感计算最成熟的 arousal 维度（circumplex 模型）；f0↑/能量↑=唤醒/紧张，语调平坦=情绪抑制。
- 数据支撑：acoustic 17 条全部 `ok`，最充分。

**② 语速-停顿节律（Speech Rhythm → 认知负荷 / 情绪抑制）—— 描述性指标**
- 构成：语速 CPM + 停顿占比 + 填充词 + 语段数。
- 可解释性：语速/停顿/填充词是焦虑、认知负荷、回避的经典行为指标。
- 数据支撑：asr 5 条全部 `ok`。

**③ 认知负荷指数（Cognitive Load）—— 复合·预测性指标** ⭐
- 构成：眨眼率 + 语速下降 + 停顿升高 + 视线漂移（后端 `context.cognitive`）。
- 可解释性：唯一完全由可用信号构成的复合预测性指标，四条证据链多模态互证，可追溯。
- 数据支撑：blink + CPM + pause + gaze 全部 `ok`。

### 明确不重点展示（避免误导）

- ❌ 反应控制（control 类）—— 若 AU 恢复前仍由头部运动代理，误导；AU 恢复后需重新核对再定。
- ❌ 微表情/微表情密度 —— 依赖 AU 帧质量，置信需验证后再上首屏。
- ❌ 任何 rPPG/心率/HRV 生理指标 —— v1 未提取。

## 四、整合落地路线（交 Cursor 实施）

### 4.1 目标形态

18 页静态原型保留为 UI 层，由 FastAPI 托管（替换现有 React dist），前端通过 `/api/*` 拉取真实 portrait.json，替换全部 mock 数据。

### 4.2 分步

1. **搬入原型**：18 个 HTML + system.js/core.js/system.css/base.css/build.py 放入 `apps/web/`（替换 React dist 或新建 `apps/prototype/`），FastAPI 挂载静态目录 + 路由映射 `*.html`（含 `/` 首页、`/profile.html` 等）。
2. **建 API 适配层**（前端 `api.js` 或后端 adapters）：
   - 复用 `GET /api/jobs/{id}` 内嵌 portrait；`GET /api/jobs` 列表；`GET /api/jobs/{id}/metrics.csv`；`GET /api/jobs/{id}/video`。
   - 扩展 `GET /api/health`（见 2.4）。
3. **前端数据绑定**：在 system.js/core.js 顶部注入 `const API = { portrait: null }`，`init()` 时 `fetch('/api/jobs/'+taskId)` 拉 portrait，替换 `seedTasks`/`metrics`/`extended`/`topics`/`transcript`/`events`/`markerData`/`heatmap` 的 mock 常量。
4. **重点指标改造**（第三节）：画像总览首屏/雷达头牌位替换为"语音情绪唤醒度 / 语速节律 / 认知负荷"三卡，弱化无数据类（标注"未提取"）。
5. **指标命名对齐**：前端显示名统一为后端 6 类真实命名。
6. **任务状态/阶段映射**：按 2.3 落地（partial/cancelled 隐藏）。

### 4.3 验收标准

上传真实视频 → 任务 done → 18 页显示真实数据（重点三指标有真实曲线/分数/证据链）→ 模型管理页显示真实 OpenFace/资源状态。
